# Гармоническое решето по пикам спектра

`audio::dsp::sieve` — покадровый оценщик f0: одно окно FFT, его спектральные пики и поиск
фундаментальной, гармонический ряд которой лучше всего объясняет эти пики. Ни треллиса,
ни памяти между кадрами: смена ноты стоит одного окна и больше ничего.

Пока это **только бенчмарк** (`#[cfg(test)]`), в конвейер не подключено: место в
приложении решето должно заработать цифрами. Цифры ниже.

Соседи: [`pitch_benchmark.md`](pitch_benchmark.md) (чем меряем),
[`pitch_detection_survey.md`](pitch_detection_survey.md) (что вообще бывает),
[`note_detection.md`](note_detection.md) (что сейчас работает в приложении),
[`../testdata/README.md`](../testdata/README.md) (живые скрипичные записи).

## Алгоритм

1. **Окно.** Ханн, длина = степень двойки ≥ `3` периода нижней ноты диапазона, окно
   прижато к самому свежему сэмплу. Задержка — половина окна: для диапазона 65–2093 Hz
   при 44.1 kHz окно 2048 сэмплов, задержка 23 мс; для скрипки (от F3) — 1024 и 12 мс.
2. **Спектр в dBFS** и **пики**: локальные максимумы не ниже `max − 60 дБ`, каждый
   уточнён параболой по трём бинам (`analysis_math::parabolic_vertex`). Берутся 40
   сильнейших. Вес пика — его высота над этим полом в дБ.
3. **Кандидаты** — `p/k` для трёх сильнейших пиков p, k = 1, 2, … пока ≥ нижней границы.
   Фундаментальная не обязана быть среди пиков (на струне G она часто слабейшая
   составляющая), а какой-то сильный обертон есть всегда, и f0 — его целая доля.
4. **Оценка кандидата** — двусторонняя, как в TWM:
   - *предсказано → найдено*: каждая гармоника до самой высокой занятой должна найти пик.
     В ячейку засчитывается лучший пик, и ячейка платит за **недобор** до среднего веса
     пика кадра (`1.5 ×` недобор): пустая — полностью, ячейка с мусорным пиком — почти
     полностью, нормальный обертон — ничего. Это отсекает октаву вниз: у f/2 каждая
     вторая ячейка — пустая или с мусором.
   - *найдено → предсказано*: каждый пик оценивается по близости к своей гармонике. Это
     отсекает октаву вверх: у 2f нечётные обертоны f висят посередине между гармониками.
   - Сито — гауссиана шириной `σ_k = √((0.5·Δf)² + (0.005·k·f0)²)` (разрешение окна плюс
     доля, растущая с номером гармоники: вибрато, неоднородность струны) **минус её
     собственное среднее по одному гармоническому шагу**. Пик, упавший в случайное место,
     даёт в среднем ровно 0; пик между гармониками — меньше нуля. Загромождённый спектр
     ничего не зарабатывает самим фактом загромождённости.
   - Итог нормирован в `≤ 1`; ниже `0.1` кадр считается беззвучным.
5. **Уточнение** — взвешенный МНК `f0 = Σ w·k·x / Σ w·k²` по совпавшим гармоникам,
   два прохода с переподбором, не дальше полутона от кандидата. Обертон с номером k
   задаёт f0 в k раз точнее фундаментальной — ради этого и смотрим на многие.

### Откуда приёмы

- Пики с параболической интерполяцией — PARSHL/SMS: Smith & Serra 1987, Serra 1989.
- Решето — Duifhuis, Willems & Sluyter 1982, *Measurement of pitch in speech: an
  implementation of Goldstein's theory of pitch perception*.
- Двусторонний матчинг — Maher & Beauchamp 1994, *Fundamental frequency estimation of
  musical signals using a two-way mismatch procedure*.
- Ядро с нулевым средним — идея ядра SWIPE: Camacho & Harris 2008.
- Компрессия амплитуд перед суммированием — SWIPE (√), Klapuri 2006 (степенной закон);
  логарифм — сильный конец той же идеи: слабые верхние обертоны смычковой струны,
  которые точнее всего задают частоту, не тонут под двумя самыми громкими.

Базовые константы подобраны на бенчмарке и живых записях. Как подбирались — ниже.
Экспериментальные штрафы H4 заданы планом заранее и в основной режим не приняты.

### Весь MDB-stem-synth, 230 треков, полоса 65–2093 Hz

| | задержка 0 | на своём пике | октавы на пике |
|---|---|---|---|
| **решето** | **84.62 %** | **94.83 %** @ 24 мс | 0.35 % |
| банк SWIPE′ (наш основной) | 83.93 % | 91.02 % @ 16 мс | — |
| SwiftF0 (внешний эталон) | 87.87 % | 89.54 % @ 8 мс | — |
| pYIN (наш `PitchTracker`, шаг 40 мс) | 72.06 % | 82.39 % @ 72 мс¹ | 0.66 % |

¹ До 2026-10-16 было 55.97 % / 62.02 %: **на 39 % звучащих кадров pYIN молчал**, при этом
на тех, где отвечал, был прав в 91.85 % — ровно опубликованная цифра pYIN. Высота была
в порядке, решение «звук/тишина» — нет: единственное беззвучное состояние треллиса
получало всю массу `1 − v`, а у Mauch & Dixon она делится на N беззвучных «близнецов»
высот. Тишина стоила в N = 840 раз дешевле модели. После деления на N молчание
39 % → 12.9 %. Оставшийся разрыв до 91.6 % из литературы — окно (6144 сэмпла против их
2048: длинное окно нужно приложению для нот до C1, но размазывает быструю высоту) и
конвенция (литература зачитывает догадку и на кадрах, решённых как тишина).

Средняя ошибка на верных кадрах — 8.9 цента. Пик решета на 24 мс — его половина окна
(23 мс) плюс огибающая (см. «A lag-sweep peak is not a group delay» в
`pitch_benchmark.md`). Во всей полосе цифры ниже (74.89 % / 83.88 %): ниже 65 Hz решето не
ищет по построению, а таких кадров в корпусе 11.7 %. «Высота в тишине» — 5.5 % беззвучных
кадров (задержка 0).

### H1: спокойствие решета на голосе

60 голосовых стемов MDB, без шума, 65–2093 Гц, 2026-10-20; выборка стоящей
правды исправлена на исходный шаг аннотации 2.9 мс, шаг оценки — 16 мс.
RPA прежний: 79.96% на лаге 0 / 94.95% на лучшем проверенном лаге 24 мс.
Октавных событий — 6.05 / **15.94 в минуту** звучащей правды, средняя серия
на лучшем лаге — 21 мс. Дрожание: медиана/p90 5.8/20.7 ¢ на лаге 0,
**5.4/16.1 ¢** на лучшем (213439 пар). Дробление — 11405/4114 = **2.77**
независимых серий оценки/правды. У сглаженного peak comb на его лучшем
лаге 64 мс — 0.44 события/мин, 2.3/7.4 ¢ при шаге 8 мс, дробление 1.34.
С ростом лага у решета растут и октавные кадры (0.20 → 0.56%), и события:
это основание для диагностики H4 у смен нот, пока не доказательство причины.
Определения, ограничения сравнения каденций и обе линии H0 —

Потеря лучшего RPA при 10 дБ — 33.73 п.п.; у сглаженного comb — 6.10,

Почти неизменный p90 не означает устойчивость к шуму: верных пар стало

Его окно 4096 и шаг 92.88 мс длиннее наших; на чистой скрипке он хуже

Полные условия и H1 — [`pitch_benchmark.md`, R1](pitch_benchmark.md#r1-детекторы-из-других-приложений-2026-10-20).

### H4: октавы у переходов и три штрафа, 2026-10-20

**Ни один вариант не принят:** на чистом голосе a/b/c дают 0.52/0.26/0.21%
октав вместо 0.56%, выше порога H4 ≤0.1%. Порог RPA ≥94.65% выдержан,
но этого недостаточно. `HarmonicSieve::new` сохраняет прежний счёт;
эксперименты выбираются только явно через `PITCH_BENCH_SIEVE_VARIANT`.

Диагностика использует исходную аннотацию 2.9 мс, без округления в ноты:
граница звука или скачок ≥50 ¢ за один шаг — «резкий переход»; ≥5 ¢ —
«движение», дополнение к стоящей правде H1. Время границы — середина
между соседними метками, расстояние — от `t − lag` до ближайшей границы
в любую сторону. Это два приближения к сменам нот: первое пропускает
плавные переходы, второе включает быстрое вибрато. Само по себе соседство
с границей ещё не устанавливает причину ошибки.

На голосе при лаге 0 — 657 октавных кадров, при 24 мс — 1806,
из них 1464 вниз и 342 вверх. В пределах 8 мс от **движения** лежат
1502/1806 = **83.17% ошибок**, при 106562/320865 = **33.21% звучащих
кадров** в той же области. Но от **резкого перехода** 1007/1806 = 55.76%
ошибок дальше 96 мс. Считать все октавы простым хвостом смены ноты нельзя;
связь с изменяющимся f0 сильная, а дополнительный штраф недобора всё же
убирает часть ошибок. Полная разбивка по расстояниям —
[`pitch_benchmark.md`, H4](pitch_benchmark.md#h4-октавы-решета-и-переходы-2026-10-20).

a вычитает из `predicted` лучший положительный вклад пика в каждой ячейке

часть существующего `mesh`, с шириной по частоте самой ячейки; соседние
шумовые пики не складываются в одну ячейку. b удваивает только штраф
за недобор k=1, не вклад найденного пика и не остальные гармоники.

прежние. Константы зафиксированы до прогонов, не подгонялись.

### Как подбиралось

Сначала на 30 треках корпуса (задержка на пике):

| изменение | RPA | что сдвинулось |
|---|---|---|
| старт: окно 4 периода (4096), штраф 0.5, порог 0.4 | 85.4 % (5 треков) | 12 % молчания на звучащих |
| порог озвученности 0.4 → 0.2 | 90.9 % (5) | молчание ушло, вылезли октавы вниз (−12, −19, −24) |
| штраф пустой гармоники 0.5 → 1.0 | 89.0 % | октавы вниз вдвое меньше |
| штраф 1.0 → 1.5, порог 0.2 → 0.1 | 91.2 % | октавы 1.5 %, растёт «высота в тишине» |
| **окно 4 → 3 периода (4096 → 2048)** | **96.6 %** | короткое окно точнее следит за движущейся высотой |
| окно 1.5 периода (1024) | 72.2 % | низкие ноты разваливаются |
| порог обратно 0.1 → 0.2 | 95.9 % | баланс с «высотой в тишине» |

Затем на живых записях всплыло то, чего корпус не показал: на трели по струне A **10 %
кадров уходили октавой вниз** (A3/B3/C4/D4 вместо A4/B4/C5/D5). Причина — штраф брался
только с совсем пустых ячеек, а при 60 дБ диапазона в нечётные ячейки субоктавы почти
всегда попадает мусорный пик, и ячейка числилась занятой. Штраф за **недобор** вместо
штрафа за пустоту: трель на A 88.4 % → 99.0 %, октава вниз 10 % → 0.6 %; корпус −0.7
пункта на пике при вдвое меньших октавных ошибках. Оценки при этом в целом ниже, поэтому
порог озвученности опущен обратно до 0.1.

## Запуск

```sh
# весь корпус (~10 с; потоков — PITCH_BENCH_JOBS, по умолчанию половина ядер)
cargo test --release --lib sieve_rpa_on_corpus -- --ignored --nocapture

# только скрипка (таблица инструментов — один раз)
uv run tools/medleydb_instruments.py
PITCH_BENCH_INSTRUMENT=violin cargo test --release --lib sieve_rpa_on_corpus -- --ignored --nocapture

# трек по отрезку записи → CSV → картинка
SIEVE_DUMP_WAV=take.wav SIEVE_DUMP_FROM=26 SIEVE_DUMP_TO=36 SIEVE_DUMP_CSV=take.csv \
  cargo test --release --lib sieve::tests::dump_track -- --ignored --nocapture
uv run tools/pitch_roll_plot.py take.csv -o take.png --key G --temperament pythagorean
```

`pitch_roll_plot.py` рисует трек на сетке нот: высота — нота, цвет — отклонение от
ближайшей ноты выбранного строя (белый — в пределах 5 ¢, красный — выше, синий — ниже),
толщина — громкость кадра. Строй — равномерный или пифагорейский от тоники `--key`,
камертон — `--a4`.

## Что видно на записях с аккомпанементом

Скрипка с оркестром (сольная линия громче сопровождения) читается чисто: вибрато,
переходы, завышенные вводные тоны. Слабое место — **сопровождение того же регистра,
сопоставимое по громкости** (орган, бурдон на открытых струнах): решето берёт самый
убедительный гармонический ряд в кадре, и местами это аккомпанемент, а не скрипка. Это
следующее, что стоит разобрать.
